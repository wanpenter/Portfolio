Car Workshop Appointment System

A full-stack booking platform that takes vehicle service appointments from a customer's web form straight into an admin's daily schedule.

01

Overview

The Car Workshop Appointment System is a web-based booking platform for a vehicle service workshop. Customers can browse available slots and book a service appointment online, while admins manage incoming bookings, customer records, and the day-to-day schedule from a dedicated dashboard.

The goal was to replace ad-hoc phone/walk-in booking with a structured system both sides could rely on — customers get a clear booking flow, and the workshop gets an organized, searchable record of who's coming in and when.

02

My role

I worked as the Full Stack Developer on this project, building the customer-facing booking flow in React/Next.js, the Node.js API layer, the MySQL schema, and the admin dashboard used to manage bookings and customers.

03

Technical breakdown

Online booking flow

A React/Next.js front end lets customers pick a service type and available date/time slot, then submit a booking request without needing to call or visit in person.

Admin dashboard

An authenticated admin view for reviewing incoming bookings, updating their status, and browsing customer and vehicle records tied to each appointment.

Customer management

Customer records are stored in MySQL and linked to booking history, so repeat customers and their service history are easy for the workshop to look up.

REST API layer

A Node.js backend handles booking CRUD operations and schedule-conflict checks between incoming customer requests and the workshop's daily capacity.

04

Challenges

01

Preventing double-booking

Two customers requesting the same slot at nearly the same time needed to be caught server-side, not just in the UI, so schedule-conflict checks run against the database at booking time rather than being trusted from the client.

02

Keeping admin and customer views in sync

When an admin updates a booking's status, that change needed to reliably reflect back to what the customer sees, so status became a single source of truth read by both sides rather than duplicated state.

03

Structuring the MySQL schema

Modeling customers, vehicles, bookings, and service types cleanly enough to support both the simple booking flow and the more detailed admin dashboard from one schema took a few iterations to get right.
